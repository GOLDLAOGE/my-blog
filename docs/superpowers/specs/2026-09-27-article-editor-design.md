# 文章编辑器升级设计

## 已确认目标

为个人博客管理后台提供默认可视化编辑、可切换 Markdown 源码的文章编辑器。用户不必手写复杂语法，即可编辑参考文章中的主要正文效果。保持现有蓝白后台风格、文章设置分类、图片上传和 GitHub 提交工作流。

参考：https://blog.anheyu.com/posts/MrnO 。参考的是公开文章呈现效果，不声称复刻其未公开的后台实现。参考站与当前 Hexo + AnZhiYu 的运行框架不同，不迁移整站。

## 方案选择

- 采用：可视化编辑 + Markdown 源码切换 + 主题正文预览。日常直观编辑，同时保留旧文章兼容性。
- 不采用纯 Markdown 工具栏：改动较小，但仍要求用户理解语法，未满足已确认的交互方向。
- 不采用 HTML/JSON 专用富文本存储：可视化扩展方便，但会改变现有文章格式及构建链路，不符合本次范围。

## 编辑范围与布局

正文区域顶部提供模式切换和按用途分组的工具栏，旁边保留现有文章设置。窄屏下设置移至正文下方，工具栏可换行，页面不横向溢出。

1. 基础排版：标题层级、加粗、斜体、引用、有序/无序列表、链接、分隔线、撤销、重做。
2. 内容插入：图片、图片说明、表格（增删行列）、代码块（选择语言）。现有封面上传与正文图片压缩/R2 上传保留。
3. 主题组件：链接卡片、提示块、折叠内容、标签页、Mermaid 流程图。通过明确字段的插入/编辑对话框操作，而非要求用户填写完整标签语法。
4. 预览：安全渲染正文，展示排版、主题组件、代码高亮、图片说明及流程图。预览不是整个站点后台，也不复制评论等运行功能。

目录由文章标题自动生成。封面、摘要、分类、标签和 SEO 字段继续使用现有表单。版权、评论、相关推荐由主题控制，不加入正文工具栏。

不增加 ECharts、AI 摘要服务、多人协作或整站迁移。

## 数据与组件边界

- Markdown 是唯一正文持久化格式；沿用当前文章 API、YAML front matter、文件标识与版本校验。
- 编辑器适配层负责加载正文、获取正文、模式切换、脏状态和上传图片插入。现有发布流程只通过这个边界访问正文，不耦合编辑器库内部结构。
- 主题组件适配层负责表单字段与当前 Hexo 标签语法的双向转换。特殊组件在可视化模式中作为可选中、可编辑的块呈现，不把复杂标签拆散成普通文字。
- 预览渲染与编辑数据分离。实现计划阶段验证成熟编辑器的 Markdown 往返能力后选定依赖；不自建通用富文本框架。
- 仅为这些功能增加必要的主题配置或兼容代码，不改其他站点设置。

## 兼容与安全

旧文章打开、切换模式、保存必须保持正文含义和未知 front matter。无法安全识别的自定义标签或原始 HTML 必须原样保留为源码块，不能静默删除或自动改写。往返转换发现不支持内容时提示用户并保留源码编辑途径。

预览不执行文章里的任意脚本、事件属性或危险 URL；HTML 预览须清理，流程图采用严格安全配置。预览失败不清空正文、不阻止回到源码修正。网络错误、上传失败和提交冲突继续展示明确错误，不丢失当前编辑内容。

发布期间锁定当前编辑与文章切换，避免保存返回覆盖用户刚输入的内容；成功后恢复编辑。保留离开未保存文章时的提醒。图片插入到当前选区，不覆盖无关正文。

## 验收标准

1. 可视化模式能插入、修改全部约定的基础排版、内容和主题组件；源码模式仍可直接修改 Markdown。
2. 可视化/源码切换往返后，文字、图片路径、表格、代码和主题组件不丢失；旧文章及未知标签有回归测试。
3. 保存后重新打开文章，编辑内容保持一致；原有 SEO、封面、分类、标签和 front matter 保持。
4. 使用一篇包含所有支持块的测试文章进行真实 Hexo 构建，核对生成的前台 HTML 与组件结构；预览正常不作为前台构建成功的替代证据。
5. 危险 HTML/URL、非法流程图、上传失败及提交冲突都有测试或明确验证记录。
6. 自动化测试与站点构建通过；桌面和手机宽度检查工具栏、对话框、表格及代码块，无页面级横向溢出。

## 交付边界

先完成设计文档审核，再编写并审核实施计划，然后实施、测试与验收。本设计文档不授权推送、合并到 main 或生产部署；推送需用户后续明确要求。
